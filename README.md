# 開発会社物語

小さな開発会社を経営するシミュレーションゲーム。
案件を受け、技術を選び、社員を育てて、会社を続けていきます。

▶ **[遊んでみる](https://kaihatsu-monogatari.vercel.app)**

```
🛒 みらい物流／ECサイト                    2,880万
   中堅 ・ 3か月 ・ 3人 ・ 人件費 1,080万
   🔬 きびしい客：報酬はとても高いが、評価がひくいと大きく減額
```

依存パッケージはゼロ。テストは Node 標準の `node:test`、画面は素の HTML + ES モジュールです。

```bash
npm test    # テスト（88件）
npm run serve   # http://localhost:8765
```

> ES モジュールを使っているため、`index.html` を直接開いても動きません。`npm run serve` 経由で開いてください。

## 元ネタ

**カイロソフトの経営シミュレーション**（とくに『ゲーム発展国』）が下敷きです。
「隠された組み合わせを探す」「社員が育つ」「年度末に決算が来る」という骨格をお借りしました。
タイトルの「〜物語」も、あの様式へのオマージュです。

借りたのは**仕組みと様式まで**で、名前・キャラクター・画像・音楽などの固有の表現は使っていません。
登場する会社名・人名はすべて架空です。

## 遊び方

```
依頼を選ぶ → 技術を選ぶ → 社員を選ぶ → つくりはじめる
      ↓
  数字がポンポン飛ぶ（見ているだけ）
      ↓
  4人のレビュアーが採点 → 入金と人件費の精算 → 社員が育つ
      ↓
  4〜5案件ごとに 年度末の決算
```

社員がいるだけで毎月お金が減ります。資金がマイナスになると倒産です。

## 面白さの芯

### 隠された組み合わせ

ジャンル3種 × 技術7種＝**21通り**の相性が、プレイヤーには見えません。
当たりを引くと数字がはっきり跳ねます。

一度試した組み合わせは記録され、次に選ぶとき ◎○△✕ で思い出せます。
試していないものは「？」のまま。**見つける楽しみは残しつつ、記憶に頼らせない**ためです。

21通りを全部覚えさせると、発見が楽しみではなく苦痛になります。

### 依頼の性格

| | 効き方 |
|---|---|
| ⚡ 特急 | 期間が1か月みじかい。人件費は浮くが、評価が低いと減額 |
| 🌱 育成枠 | 報酬は3割安いが、経験値が2倍 |
| 🔬 きびしい客 | 報酬1.6倍。ただし基準を割ると45%まで減額 |

**きびしい客は、当てれば +1,087 / 外せば −571。** 相性を知っているジャンルなら勝負に出る、
知らないなら手堅く、という判断になります。

最初は報酬倍率だけで差をつけましたが、外しても傷が浅く、どの条件も結局は得になっていました。
**合格ライン（下回ると減額）という崖**を入れて、はじめて博打になりました。

### 育つ

案件で出した数字が経験値になり、レベルが上がると出る数字が増えます。
レベルアップのたび45%でスキルを覚えます。

効果は「出る数字を増やす」より**その人らしさが出る**方向に寄せてあります。
指標系のスキル（🔍レビュー鬼・✨美意識など）は、数字ではなく「手の伸びやすさ」を押し上げます。

🤝**教え上手**だけは毛色が違い、同じ案件の仲間の経験値を増やします。
育てたい社員と組ませる意味が生まれ、誰を入れるかが投資判断になります。

## 作り方の話

### 3本外したあとにできたもの

これは4本目です。前の3本は、遊んでみて「面白くない」と分かって作り直しています。

| | 増える・育つ | 判断 | 反応 |
|---|---|---|---|
| 放置ゲー | ✅ | ❌ | 「面白みがない」 |
| PMシミュレータ | ❌ | ✅ | 「焦らない・迷わない」 |
| **これ** | ✅ | ✅ | 「面白くなった」 |

**判断だけでも、増えるだけでも足りない。** 放置ゲーは構造上ほぼ判断が無く、
PMシムはメンバーが消耗するだけで一切成長しませんでした。

### 作る順番を途中で変えた

前の2本は「純粋関数 → シミュレータ → UI」の順で作り、どちらも**数字は正しいのに面白くない**という結果でした。

カイロソフト系の面白さは数字ではなく**手触り**（増える・飛ぶ・育つ）にあり、シミュレータでは測れません。
そこでこの作品では、**最小の動くループを先に画面で作って**手触りから確認しました。

そのために `work()` は「1回ぶんの作業」だけを返します。まとめて計算すると、
演出のために UI 側でルールを再現する羽目になります。

### 手触りが成立した3条件

1. **待たされない** — 190msごとに何かが起きる
2. **手を離しても進む** — 開発中は眺めるだけでよく、その時間があるから気持ちよさが成立する
3. **判断は前に置く** — 依頼・技術・人選を決めたら、あとは眺める

**「決める時間」と「眺める時間」が分かれている**のがこのジャンルの構造です。
ここが混ざると、ずっと考えさせられる画面になります。

### バランスは体感ではなく実測で決めた

| 直したもの | 症状 |
|---|---|
| 評価の満点 | 100回中**97回**が満点だった。相性倍率とクリティカルが二重にかかっていた |
| 月給 60→120万 | 安すぎて何をしても黒字になり、資金が「ただ増える数字」だった |
| 評価の基準 | 大型案件は作業回数が多いぶん自動的に高評価になっていた。作業回数に比例させて揃えた |
| 依頼の条件 | 倍率だけでは外しても傷が浅く、どの条件も得だった。合格ラインを入れた |

## ファイル構成

| ファイル | 責務 |
|---|---|
| `src/dev.js` | 1本の案件をどう作るか（相性・作業・評価）。純粋関数のみ |
| `src/company.js` | 案件をまたいで何が残るか（育成・資金・時間・決算・保存） |
| `src/rng.js` | 種から決まった順番で乱数を作る。ゲームのことは何も知らない |
| `src/ui.js` | 画面の描画と演出。ルールは一切書かない |
| `test/*.test.js` | テスト88件 |

`dev.js` と `company.js` を分けているのは、混ぜると案件のバランス調整のたびに育成側まで壊すからです。

## 設計上の注意点

- 乱数は**決定的**（種から生成）。`Math.random` だと結果が出るまでやり直せてしまい、学習が成立しない
- ルールの層で `Date.now()` を呼ばない。時計に触っていいのは `ui.js` だけ
- 相性表はプレイヤーに見せない。見せると、ただの正解表を読む作業になる
- 減額や失敗は**理由まで出す**。黙って数字を小さくすると理不尽に見え、次の判断につながらない
- 新しい要素を足したら「どれかが死に選択肢になっていないか」を必ず測る。
  実際、技術を7種に増やしたとき Python がどのジャンルでも活きない死に技術になっていた（テストで発覚）
- 画面の起動テストを置く。ルールの関数だけをテストしていた時期に、
  未定義の参照で画面が真っ白なのにテストは全部通っている、という状態を作ってしまった
